# Kontur.Talk Meeting Inbox

Неофициальный локальный прототип для преподавателя: собирает сообщения общего
чата и личные сообщения участников встречи Контур.Толка в одно отдельное окно.

Ученики могут писать в общий чат или преподавателю обычные личные сообщения внутри
Толка. Приложение показывает всё в единой ленте с именами отправителей и метками
`ОБЩИЙ`/`ЛИЧНО`; личные сообщения по-прежнему не видны другим ученикам.

## Важно

- На компьютере преподавателя нужны Windows и десктопное приложение Контур.Толка.
  Ученикам устанавливать дополнительное приложение не требуется.
- Использует Windows UI Automation, а не официальный API Толка.
- Не запрашивает логин, пароль, токены или ключи и не перехватывает сетевой трафик.
- Открытые приложением сообщения становятся прочитанными в Толке.
- Интерфейс Толка может измениться и сломать прототип.
- Локальный лог содержит тексты сообщений. Он сохраняется в
  `.tmp/talk_messages.jsonl`; каталог `.tmp` исключён из Git.

## Установка

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```powershell
git clone https://github.com/AlexeyMalyshkinMIPT/kontur_talk.git
cd kontur_talk
uv sync
```

## Быстрый запуск

1. Запустите встречу в десктопном приложении Контур.Толка.
2. Откройте чат и обязательно нажмите **«В отдельном окне»**. Должно появиться
   отдельное окно с системным заголовком `ktalk`.
3. Оставьте отдельное окно на вкладке **«Общий чат»**.
4. Запустите:

```powershell
.\start_talk_inbox.cmd --organizer "Имя преподавателя в Толке"
```

Или напрямую:

```powershell
uv run python talk_private_chat_window.py --organizer "Имя преподавателя в Толке"
```

Параметр `--organizer` скрывает исходящие сообщения преподавателя из общей ленты.
Если его не указать, приложение покажет все доступные сообщения.

После запуска в заголовке окна отображаются текущее состояние и количество
сообщений, например `Толк · подключено · 17 сообщений`:

- `подключаюсь` — приложение ищет открытое окно `ktalk`;
- `подключено` — общий и личные чаты отслеживаются;
- `ошибка` — интерфейс Толка недоступен или изменился.

## Управление окном

Окно по умолчанию закреплено поверх остальных и пропускает клики насквозь, поэтому
не мешает работать с Толком, браузером или доской под ним.

- Перетащить окно — потянуть за обычный системный заголовок.
- Закрыть или свернуть — использовать стандартные кнопки в заголовке.
- Прокрутить ленту или выделить текст — удерживать `Ctrl` во время действия.
- Полностью включить или выключить интерактивность — `Ctrl+Shift+F10`.
- Не закреплять окно поверх остальных — запустить с `--no-topmost`.
- Не пропускать клики насквозь — запустить с `--no-click-through`.

Для однократной загрузки всей старой истории добавьте `--include-history`; этот
режим активно переключает диалоги во время старта.

## Если не подключается

1. Убедитесь, что встреча открыта именно в десктопном Толке преподавателя.
2. Убедитесь, что чат вынесен кнопкой **«В отдельном окне»** и это окно не закрыто.
3. Не запускайте два экземпляра приложения одновременно.
4. Посмотрите `.tmp/talk_runtime_errors.log` — туда записываются ошибки фонового
   чтения и интерфейса.
5. Тексты уже пойманных сообщений находятся в `.tmp/talk_messages.jsonl`.

Если отдельное окно чата закрыть, приложение перейдёт в переподключение. После его
повторного открытия наблюдение восстановится автоматически.

## Консольный режим

Один проход по общему и личным чатам:

```powershell
uv run python talk_private_message_reader.py --once --include-read
```

Постоянное наблюдение:

```powershell
uv run python talk_private_message_reader.py --watch --organizer "Имя преподавателя"
```

## Как это работает

Приложение читает UIA-дерево отдельного окна `ktalk`, пока оно находится на
«Общем чате». Когда Толк показывает счётчик `ЛИЧНЫЕ N`, приложение кратко переходит
в личные, открывает только непрочитанные диалоги и возвращается в общий чат. Поэтому
в спокойном состоянии watcher не переключает вкладки и не забирает фокус у других
приложений. Повторы подавляются по каналу, отправителю, отображаемому времени и
тексту сообщения.

Режим кликов насквозь реализован через проверку области окна (`WM_NCHITTEST`), а не
через layered-прозрачность. Поэтому содержимое ленты продолжает перерисовываться,
а системный заголовок остаётся доступным для перемещения окна.

Это MVP для проверки сценария. Он не является официальным продуктом СКБ Контур.
